# kagan look

The window has a title bar with a button for each sidebar, a left sidebar of projects and threads, the chosen thread's terminal, and a right sidebar with a tab row of panels, the Browser and terminals (decisions 48 and 118). The title bar carries the thread title and muted project name, with plugin header commands, Stop and the thread menu before the right toggle. The native window title is the thread title and project name. Both sidebars can be dragged to resize and hidden, with a button or a shortcut (`ToggleSidebar`, `ToggleRightSidebar`). Their open state and widths are preferences (`main.left-sidebar`, `main.right-sidebar`, `main.left-width`, `main.right-width`, one set per window; `main` is the window), so `kg preference set` moves them. It has no back, forward, or Skills. Its colors come from the Workbench theme tokens below. The window paints no literal colors of its own.

On macOS the menu bar is kagan, File, Edit, Thread, View, and Window. kagan has About, Check for Updates…, Settings…, Hide, Hide Others, Show All, and Quit. About shows the name and the version. Settings… is the same page as the gear (Cmd+,). Hide is Cmd+H, Hide Others is Cmd+Option+H, and Quit is Cmd+Q. When a program is running, Quit asks once: “Quit kagan?” and that those programs will stop and resume when kagan opens again, with Quit and Cancel. Nothing running quits at once. There is no setting to skip the question. `kg window quit` does not ask. Closing the window leaves programs running, and clicking the Dock icon opens the window again. The Dock badge counts threads marked needs you, including while the window is closed; it disappears when none need you. File is New Thread (Cmd+N), Add Project… (Shift+Cmd+O), and Close (Cmd+W). Edit is Undo, Redo, Cut, Copy, Paste, and Select All. Copy and Paste in the terminal are the terminal's own copy and paste. Thread is Stop, Start Again, Rename…, and Archive, then Next Thread (Shift+Cmd+]), Previous Thread (Shift+Cmd+[), Next Thread Needing You (Option+Cmd+J), and Thread 1 to Thread 9 (Cmd+1 to Cmd+9). View is Bigger, Smaller, Actual Size, Left Sidebar, and Right Sidebar. Window is Minimize (Cmd+M), Zoom, and Close (Cmd+W). Close leaves programs running.

UI text is Inter, 13 px. Page titles are 15 px semibold, metadata 12 px, section headers and hints 11 px; diff code uses the terminal face at 12 px. Terminal text is JetBrains Mono, 12 px by default. Bigger, Smaller, and Actual Size in View use Cmd+=, Cmd+−, and Cmd+0 to change the saved terminal size from 9 to 24 px in steps of 1. Thread rows are 28 px and project headers are 24 px, with 8 px of horizontal padding and an 8 px corner radius. The list is 256 px, or its saved width, and extra window space goes to the center. Projects with the same name show the name, a dot, and the shortest folder path that tells them apart. The name keeps about four characters and an ellipsis, and the folder path cuts from its start, so its end stays visible. The header stays on one line. The accessible name is the visible label, such as “webapp · team/client”, and the tooltip carries the full name and path. The thread column has 16 px of padding, and the terminal text keeps that leading inset on the terminal background. The terminal meets the sidebar border, and the ended line uses the terminal background. A live cursor is filled only while the terminal and window have focus; otherwise it is a 1 px outline. A question and the approval use a 12 px radius.

**Thread list.** New thread is at the top. Projects follow in the person's order, with Personal last, each with its threads under it. Drag a standard project header onto another to move it: the top half of the target places it before, the bottom half after; Personal cannot be dragged [decision 132]. When two projects share a name, the shortest parent folder that tells them apart follows the name, in muted, and the same words are the disclosure and new-thread labels. A disclosure chevron, +, and project menu appear on hover or focus. The chevron sits before + and takes no room until then. The disclosure hides or shows threads for this window, and starts open. The project name selects the project and shows its New thread form. Enter on a focused project starts the picked program there. + starts a thread in it. Child threads are indented under their parent, with a guide and a disclosure to hide them. Each level indents 24 pt, up to three levels; deeper threads share the third level's indent, so their actions stay inside the sidebar. Archive and thread actions appear on hover or focus. The thread menu on a row acts on that row and leaves the screen as it is; Rename shows the row first. Add project is an icon in the footer. Each thread row carries a mark, then the title, and a pin glyph when the thread is pinned. The mark spins while the thread is busy, shows a circle with an exclamation mark in `needs` when it needs you, an octagon with a cross in `failed` when it failed, a 14 px check in `working` when it finishes unseen, a 4 px muted dot when a live thread is idle, and a 14 px muted dash when the program has ended. Each mark is drawn in a 16 px slot and has a tooltip with the state word. The check lasts until that thread is shown; needs-you and failure take precedence. The dash is a stop or an exit, including exit 0, and only while that thread is idle and has no other mark. Failure and needs-you keep their own marks. No state depends on color alone. A thread that is running and not busy keeps the idle dot. The title stays in the normal ink. The row's value is the state word: busy, needs you, failed, done, idle, or ended. An Archived icon in the footer appears when a visible thread is archived. It opens a searchable list of archived threads. Restore brings one back, and the program stays stopped. When a worktree could not be removed, that row names the files git would keep, in the `failed` token, and offers Remove again. A selected row, project or thread, fills with the `raised` token. The `ring` token draws only for keyboard focus, so a mouse click leaves no box around the row. Up and down move between rows and do not open them. Each row is one Tab stop. Its hover controls (the chevron, +, the project menu, Archive, and the thread menu) are not Tab stops. They show on hover or focus, and a mouse, or `kg ui click` on a shown control, reaches them. Left folds a focused project or a thread that has children, and Right unfolds it. New thread on a focused project starts a thread in that project. The hover controls are 24 pt buttons. Add project is not a Tab stop; Archived in the footer is. The New thread row at the top is a button, not a row: Tab does not reach it, and Cmd+N starts a thread.

**Thread.** The project name selects the project. + opens the program line with the title New thread. On the new-thread screen, New worktree and Project folder each name the branch, and one line under them says where the run writes: a worktree's folder under the data folder, cut from its start with the full path in a tooltip, or the project folder itself. New worktree asks which local branch to start from. Cancel leaves the screen as Escape does. Start is the default commit and shows its key, Enter, and while kagan waits for the setup script one line says why Start is off. The form is pinned near the top of the centre, and Cancel and Start are its last part, under the fields, which scroll above them. The program list shows eight rows, and a line under it says how many more there are; the list scrolls to the rest. Project folder stays on the current branch, or checks out a local branch, or creates one from a local branch [decision 170]. A worktree names `.kagan/setup`. Show script opens the text read from the pinned commit, in the monospace face, and caps the length. After a setup failure, the primary button reads Retry setup, and the line above it says to fix .kagan/setup and retry. It runs the failed script again in that same worktree. After the script changed, the button reads Start. The open thread is a terminal. The person types into the program they named. + in the title row, before Stop, opens an extra terminal (decision 110). While one is open, a row of tabs over the terminal shows the program's name first, then Terminal 1, Terminal 2 and so on, each extra one with a close ×; the shown tab is filled and the row scrolls sideways rather than widen the center. When a terminal printed a local link, an outline Open localhost:3000 button sits at the right end of that row, and the row shows for it even with no extra terminal; it is not in the title row, where it would cover the centered title in a narrow window (decision 112). A plugin command with `"header": true` and `"when": "thread"` is a small ghost button before Stop, labeled with its title (decision 129). Stop ends it. Rename, Pin, and Archive sit in the menu with the title. Archiving selects the next thread that stays, or the previous when it was the last, skipping threads that archive with it, and shows Archived “title” with Undo for 10 seconds. Undo brings those threads back. A click on the title does not rename it. Enter commits a rename and Escape cancels it, and focus returns to the terminal. A click elsewhere closes the field and leaves focus where the click put it. A program that has ended says why, on the line under the terminal: Stopped, Exited with code N, Ended by signal N, Ended when kagan quit, or Stopped while starting. Any other failure shows its error. Start again is the primary button on that line. New thread here… sits beside it when the thread has a folder: it opens the new-thread screen, titled New thread beside the thread's title, with that folder fixed, and Escape returns to this thread [decision 194]. If older scrollback was not kept, or the screen was outside the geometry or the 4 MiB bound, the same line says so. A crash while the program was still running says that no output was saved for that run. Save diagnostics is in the thread actions menu. The ended line also has that button when the program failed, was interrupted, or its screen was not kept in full. A clean stop or an exit 0 leaves the line to the cause and Start again. The cursor is hidden once the program has ended; the stored screen still has it.

**Rail.** The rail at the left edge is 48 points wide. It holds the kagan mark, Threads, one icon per plugin with a left tool, one icon per center page below them (tooltip: the page title), Manage plugins, New plugin…, and the Settings gear at the bottom. Each icon has a tooltip, with its live key when it has one. The selected icon fills with the `raised` token, and the `ring` token draws only for keyboard focus. A left tool's icon shows that tool's body in the list column, below the threads. Choosing it again closes the body. The kagan mark is drawn in `ink`, not `accent`, at the size of the other icons, with the tooltip and name kagan. It is a Tab stop. A click, Enter or Space opens a menu of About kagan and Settings… under it; Settings… opens Settings and never closes it. Escape closes the menu and gives the keyboard back to the mark. A click outside closes it and leaves the keyboard where the click put it, or on the mark when the click took no focus. Closing a Settings opened from the menu gives the keyboard back to the mark. The rail is the host's, so the mark stays when a plugin draws the thread list and when the sidebar is drawn over the center (decision 108). Manage plugins opens Settings → Installed. New plugin… starts a Personal thread with the first installed agent and the prompt `Build a kagan plugin that `, pasted without Enter after the screen settles. A page replaces the center: one title, Close on the right, then the plugin's body, inset by the same 16 px as the title. Close returns to the terminal, and so do Enter and Space while Close itself has focus. Escape returns unless the focused plugin control handles it first. A page and a file review do not show together.

**Right sidebar.** A tab bar sits at its top. It has a tab for Changes and Details for the shown thread, and for Questions only while something waits. Questions comes first, so a waiting question shows first; Details comes after Changes. Open right plugin panels follow as tabs with a close button, then the Browser and each extra terminal (Terminal 1, Terminal 2) while they are open, and Preview while a file is open, also with one; the built-in tabs have none. A trailing `+` (Add tab) lists Browser while it is closed, Terminal for a thread that is not archived, and the declared right panels that are not open. Opening the Browser or a terminal selects its tab, opens the sidebar when it is hidden, and gives it the keyboard. The Browser tab is an address field over one web page (decisions 117, 118, 131 and 161). While a thread drives it, one row takes the place of the address field: a `type_small` muted sentence "Driven by <thread>" with the URL and one `Button` (Stop agent), and the page runs edge to edge below it (decision 143). One selected tab's body fills the column. While the column is drawn, a Full screen button at the end of the tab bar gives it the window beside the rail and below the title bar, in place of the threads and the terminal. Pressing it again, closing the column, or opening a left tool or a page gives the window back. It is not saved. A click, Enter or Space on a tab selects it. Closing a tab moves the keyboard to the selected plugin tab's body, the Browser's address field or terminal, or to the `+`. Hiding the sidebar while it has the keyboard gives the keyboard to the program's terminal. With no thread, nothing waiting and no plugin that declares a right panel, the column is hidden. The right toggle reports the panels that are drawn. When the window hides them to keep the center at 480, the toggle says hidden. While something waits, it draws the count in `needs` beside the toggle. The toggle's value stays `hidden, N waiting`. A person-only question, such as a plugin install or a project removal, opens those panels over the center by itself, with Questions shown, and focus stays where it is. With the panels hidden and the shown thread changed, the toggle draws the count in `muted` and its value reads `hidden, N changed`; its tooltip says the thread has changed files. Pressing it then draws those same panels over the center's right edge, 320 wide, and leaves `main.right-sidebar` as it was. A closed right sidebar in a window wide enough for the column opens that column and saves the preference, including when those panels are already drawn over the center. During review the toggle opens the overlay instead. Opening either side overlay closes the other; menus can still open over it. Escape, or a click outside the panels, closes that drawing and returns focus to the previous control when available, or to the review or toggle otherwise. With no thread, nothing waiting and no right plugin panel, the toggle is disabled and its tooltip says why. Widening the window enough puts the panels back in the column when that preference is open. Questions lists every question that waits, with the thread's title above it, and approvals first. Delete, Remove, and Install use those verbs with Cancel. Cancel is focused, and Delete and Remove use the danger color. A question shows its options. Changes lists the shown thread's changed files. Each row shows the kind (A, M, D, R), the path, and the counts. A count of zero is left blank. In a git folder the Uncommitted and Branch scope that is selected stays filled; elsewhere Changes says "Not a git folder." without those controls. Opening a file shows its review in the center: a scope and counts above the patch, a filterable tree at the right, and comments under their lines. Long lines scroll horizontally and fade at the right edge. Wrap lines in the file bar, or Alt+Z, wraps them to the visible width without a fade or horizontal scroll; the choice is saved as `main.review-wrap` and defaults off. Line numbers and the comment control stay on the first visual line, and comments stay beneath their line. A single gutter shows old numbers for removals and new numbers for other lines. Code on each line uses the theme's syntax colors, from the whole file when its text is available and from the hunk otherwise; a language with no grammar stays one color. Added and removed rows keep their tint, and a changed word keeps the stronger tint (decision 174). Added and removed rows use the `added` and `failed` tokens; unchanged runs expand on click. The right sidebar hides while the review is open and returns afterward. Opening a review closes the right overlay and gives the review the keyboard, so j moves at once. Details lists, each under a small muted label, the folder with a Copy button, the environment (Project folder, Worktree or Personal folder), the program line, and in a git folder the branch (or Detached), the base branch with how far the branch is ahead and behind it, and the last five commits as a short rev in the terminal face and a subject. Outside git it says "Not a git folder." It reads again each time the thread is shown and every two seconds while it is open, like Changes (decision 111). Viewed marks follow the file until its patch changes. The footer counts comments and files, and Discard clears saved comments and offers Undo. A line’s comments scroll above three rows. Enter adds a comment, Shift+Enter adds a line, and Escape cancels the draft. Send review to terminal adds a focused nonempty draft first, then closes the review and shows the program’s terminal tab. Once that terminal has taken its size, it pastes one editable line into it without submitting it. If the paste is refused, the terminal says Not sent and the comments stay. Comment line breaks are flattened to avoid submitting lines to a shell. Cmd+Enter sends the review (Ctrl+Shift+Enter off macOS). Use j and k for files in visible tree order, n and p for changes, v for Viewed, and Escape to return to the terminal. Tree rows take focus; arrows, Home, End, and Enter navigate and open them. Opening that review leaves a plugin page, and opening Settings closes the review. **Preview** shows one file read-only. The review file bar has a Preview button, and Preview in the command list (Shift+Cmd+V) picks a file. Inside a review it previews the file on screen instead. The header shows the path in muted type with the name semibold, the size, Copy path, and the tab's close. One file at a time: asking for another file replaces the content. UTF-8 text and Markdown scroll, a CSV or TSV draws as a table that scrolls sideways, and a PNG or JPEG fits the column with its pixel size and byte size underneath. Markdown is selectable and fetches nothing: a remote image draws nothing and a link opens only http and https. When text is cut, or a file cannot be shown, one muted sentence says why, never a blank tab. A thread switch closes it. Ctrl+Shift+V is the chord off macOS.


With no thread open, the center shows the kagan mark, 64 points, in `muted` at 30% opacity, centered above Run your agent in a thread and its two buttons. It is decoration: it has no name or role and takes no focus or click, and the content stays in view at the smallest window (decision 108).

**Update notice.** When a check finds a newer kagan, one line sits over the center with a `line` border under it: kagan 0.2.0 is available, then Release notes, then Install when kagan quits and Restart and install… for a copy kagan replaces, Copy command for a Homebrew copy (the line says `brew upgrade --cask kagan`), or nothing more for a `.deb` or source build, then Not now. While it downloads, the line says Downloading kagan 0.2.0…; once it waits for quit, kagan 0.2.0 installs when kagan quits, with Restart and install…; downloaded but not waiting for quit, kagan 0.2.0 is ready to install, with both buttons. Restart and install… asks Install kagan 0.2.0? and says those programs will stop and resume when kagan opens again (decisions 114, 115 and 171).

**Activity strip.** One line across the bottom of the window, below the sidebars and the center. Closed it is 28 px: a 6 px dot and one muted 12 px sentence, `1 agent working`, `N agents working`, or `Quiet`. The dot is `working` while a program is busy with a reply and `muted` when none is. After the sentence come buttons, each its own Tab stop: `N needs you` in `needs` runs Next Thread Needing You; `Update available` runs the update notice's main action for this install (Restart and install…, Copy command, or Release notes), and its tooltip names that action; and `Installing <source>`, the folder or git source, opens Settings → Installed while a plugin install runs. At the right of that row, after the install line, at most four plugin status items in plugin-id order: each is the approved title in `muted_foreground`, then one 12 px line in the tone's color (`working` for busy, `needs`, `failed`, and `muted` for quiet), shortened with an ellipsis and bounded to about 200 px. An item that names a command is a button that runs it; its tooltip names the command and its key, after the plugin's own text when it sets one. They show only while the `plugin-status` preference is on and the window is at least 720 px wide; a narrower window keeps the host's summary and hides them. Any item the strip does not draw, past the fourth or in a narrow window, leaves a muted `+N` with a tooltip that names it. Last is an outlined button labeled `Activity log`, with an icon, a tooltip and its key (Cmd+Shift+E); its accessible name is `Activity log`, and its value is `shown` or `hidden`. The outline is the cue: needs you, update, install and a plugin item with a command are outlined buttons, while plain status text is not. Open, the strip grows by seven 20 px rows, newest last, all muted, and the dot and sentence stay on the first row. With nothing in the log, the first row says Nothing has happened yet. The strip never takes the keyboard itself: the log button takes focus only when the person clicks or tabs to it, and Escape while focus is in the strip closes the log. A question, a turn or an update never moves focus into it. It is the host's: no plugin draws in it. Its ids are `activity-strip`, `activity-summary`, `activity-needs`, `activity-update`, `activity-install`, `activity-plugin-<plugin id>`, `activity-toggle`, `activity-log`, `activity-empty` and `activity-row-<n>`. A status item with no command takes no click or focus; its tooltip shows on hover. A status item is reported as role Status with its title as the name and its text as the value, and an item with a command is a Button.

Settings takes over the window. It opens with Cmd+, (Ctrl+Shift+, off macOS), the gear at the bottom of the rail, the kagan mark's menu, or `kg settings open`. The right sidebar hides. The page scrolls through Appearance (Theme, Mode, Terminal text size, Plugin status), Agents (integration and notifications), Updates (the version with Check now and what the last check found, and Check automatically), Keyboard, and Plugins (Installed), in that order. Section headers use caption style and cards have a 24 px inset. Keyboard rows are 24 px and grouped by Window, Thread, New thread, and Review, showing only keys that apply in each place. There is no search or section menu. Opening a section from elsewhere scrolls to it. The Settings header has Close on the right. Close or Esc leaves, and both sidebars come back as they were. Focus returns to the control that opened Settings, or to the thread when that control is gone. Enter and Space close only while Close itself has focus. Appearance shows a missing or invalid theme file as an error and keeps the chosen id. Agents says that turning integration off drops the extra arguments for claude and codex, while every program still receives the KG_* variables and kg on PATH. Plugin settings and views remain available. A plugin setting shows a save error on its row. Text saves on Enter, shows that it is saving until that reply, keeps a newer draft, and Revert restores the saved value. An unsent draft is not saved. Installed says what an enabled plugin added, and offers Update only for a git source. An empty Installed section says plugins add panels, pages, commands and tools, and names `kg plugin new <name>`. `kg theme get` and `kg theme set` choose the theme file.

## Theme files

`fjord` is the default: Ember Fjord, a cool Nord-like graphite with one ember accent. `kg theme set` selects an id and a mode: `light`, `dark`, or `system`, which follows the operating system's light or dark mode and changes live with it. `system` is the default. Three themes ship with the app: `fjord`, `ember` and `grey`. Ember and grey are the files in [docs/themes](themes/).

The terminal has its own set, in an optional `terminal` object on each mode. It holds `bg`, `fg`, `cursor`, and the 16 ANSI colors by name: `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`, and the same eight as `bright…`. The terminal box is painted with `bg`, and the cursor with `cursor`. Ember Fjord gives the same set in both modes, and the table below shows its values.

A theme without a `terminal` object keeps the xterm colors, with the window's `bg` as the terminal background and `ink` as the text and cursor color. A theme file requires `working`. Only `hover`, `added`, `selection`, `input`, `look`, `terminal` and `highlight` may be omitted.

**Density and type.** An optional top-level `look` object sets the spacing, radii, text sizes and row heights of the host and the plugin web panels, in whole pixels. It is the same in light and dark. Every field is optional; a file without `look` keeps the numbers below, so an older theme paints exactly as before. An unknown field inside `look` is refused like any other unknown field. A value outside its range is refused with the field named: `space` 0 to 64, `radius` 0 to 32, `type` 8 to 48, and `row` and `control` 16 to 64.

| Field | Default | Use |
|---|---|---|
| `space.xs` | 4 | between a mark and its label |
| `space.sm` | 8 | row padding, the gap inside a control row |
| `space.md` | 12 | sidebar padding, a panel body |
| `space.lg` | 16 | between a title and its control |
| `space.xl` | 24 | a settings card inset, the settings page |
| `space.xxl` | 32 | web panels only for now |
| `radius.xs` | 6 | a rail icon button |
| `radius.sm` | 8 | a list row |
| `radius.md` | 8 | a general control; the GPUI Kit radius |
| `radius.lg` | 12 | a question or the approval |
| `type.caption` | 11 | section headers and hints |
| `type.small` | 12 | metadata and tabs |
| `type.body` | 13 | body text |
| `type.title` | 15 | a page title |
| `type.mono` | 12 | diff code and other monospace text |
| `row` | 28 | a list row, such as a thread row |
| `control` | 24 | a compact row that holds controls, such as a settings keyboard row |

No host view uses `space.xxl` yet; a plugin web panel still gets it. A theme can set density and type without a new file version: `docs/themes/ocean.json` carries an example.

A few sizes are not on the six-step space scale and stay fixed: 2 px gaps (a settings title to its note, and the inset inside a segmented control), 6 px gaps (between rail icons and in the title bar's thread heading), the 20 px height of one item in a scope segment, a 24 px child-thread indent, the 36 px tab bars and terminal strip, and the 80 px left inset the macOS traffic lights need. They are the same in every theme.

```json
"look": {
  "space": { "xs": 4, "sm": 8, "md": 12, "lg": 16, "xl": 24, "xxl": 32 },
  "radius": { "xs": 2, "sm": 2, "md": 2, "lg": 4 },
  "type": { "caption": 11, "small": 12, "body": 13, "title": 15, "mono": 12 },
  "row": 26,
  "control": 22
}
```

Each value is also a CSS custom property on a plugin page: `--space-xs` to `--space-xxl`, `--radius-xs` to `--radius-lg`, `--text-caption`, `--text-small`, `--text-body`, `--text-title`, `--text-mono`, `--row` and `--control`, with `px` already applied. The page also gets `--selection` and `--input`, with the other color tokens.

These ratios describe the fjord palette. The window does not report them, and it does not repair colors.

Use `<dataDir>/themes/<id>.json`. `KG_DATA_DIR` overrides the data directory; otherwise it is `~/.kagan` (`USERPROFILE` on Windows). IDs are nonempty lowercase ASCII letters, digits and dashes. `fjord`, `ember` and `grey` are reserved. Paths, dots and traversal are rejected by the operation boundary. A plugin theme is a file inside the plugin, declared in its manifest, with the id `<plugin id>/<theme id>` ([plugin-api.md](plugin-api.md)).

Copy [ocean.json](themes/ocean.json) as a starting point, or run `kg theme new <id> [--from <theme>]`, or press New theme… in Settings → Appearance. The file contains a `name`, a complete `light` palette and a complete `dark` palette, and may set `look`.

A theme file is a regular file of at most 64 KiB, and its `name` is one line of at most 64 characters. Both palettes are required, and so is every token except `hover`, `added`, `selection`, `input`, `terminal` and `highlight`. Colors must be opaque `#RRGGBB`; unknown fields, missing fields, invalid colors and blank names are errors. This format projects onto the pinned GPUI Kit `ThemeConfigColors` roles. It is not CSS or a GPUI Kit theme file. The window paints no literal colors of its own.

An optional `highlight` object gives the review and the Editor their syntax colors. `light` and `dark` each hold one theme in [Zed's syntax format](https://zed.dev/docs/extensions/languages#syntax-highlighting): a `name`, an optional `appearance` (`light` or `dark`), and a `style` with `syntax` and the status colors (`error`, `warning`, `created`, `modified` and so on). Each syntax name (`keyword`, `string`, `comment`, …) takes a `color`, a `font_style` (`normal`, `italic` or `underline`) and a `font_weight` (100 to 900 in steps of 100). Colors are `#rgb`, `#rgba`, `#rrggbb` or `#rrggbbaa`. `kagan` keeps the object as it is and hands it to GPUI Kit's `HighlightTheme`, so a theme file does not need to name every token. A theme without `highlight`, or with only one of the two modes, keeps the GPUI Kit default syntax for the missing mode. A bad value is refused with its field named, the way a bad palette is.

```json
"highlight": {
  "dark": {
    "name": "Ember code",
    "appearance": "dark",
    "style": {
      "syntax": {
        "keyword": { "color": "#f0905f" },
        "string": { "color": "#a8c98e" },
        "comment": { "color": "#a7afbf", "font_style": "italic" }
      },
      "editor.background": "#22262f"
    }
  }
}
```

The theme picker shows a card per theme: built in, then the person's files, then plugin themes, each labelled Built in, Your file, or the plugin's name. A file that does not load shows its id and error on its card, and cannot be picked. The theme entity reads the folder on the background executor every 500 ms and follows the plugin host. Saving, replacing or adding a JSON file updates the catalog. When the chosen file stops loading, its last good colors stay and a toast says so once; a chosen file that never loaded uses the default palette. When the chosen theme is missing, Appearance shows that line under the cards and the default palette is used for the selected mode; a chosen plugin theme that goes away says so once in a toast. The chosen ID is retained, so a corrected or restored file, or a re-enabled plugin, becomes the selected theme again. Only `kg theme new` and New theme… create a file, and never over an existing one; no file is repaired.
